Adding a New Graph
=============================

This is an overview of the files involved and the changes needed when adding a new graph type.
The `IshikawaDiagram` graph (a direct `Graph2D` subclass) is used as an example throughout.
`BulletChart` is a good second reference for a graph with more options.

For more detail on saving and loading, see [serialization.md](serialization.md).
(Note that the ReportBuilder now lives in `src/reporting/` rather than `src/base/`.)

Graph Class
=============================

Create `src/graphs/ishikawadiagram.h` and `src/graphs/ishikawadiagram.cpp`.

- Derive from `Graph2D` (or `GroupGraph2D` if the graph groups categorical data).
- Use `wxDECLARE_DYNAMIC_CLASS` in the header and `wxIMPLEMENT_DYNAMIC_CLASS` in the source.
  This is what makes `IsKindOf(wxCLASSINFO(...))` work in the application code below.
- Hide the axes in the constructor if the graph doesn't use them (see `WaffleChart` for the pattern).
- Implement `SetData()`, `RecalcSizes()`, and `SetAutoAccessibilityAttributes()`.
- Throw `std::runtime_error` from `SetData()` if a column can't be found.
- Expose getters for everything that needs to be saved or shown in the edit dialog (e.g., the effect text and the original branch definitions).
- If the graph has no legend, override `CreateLegend()` as `[[deprecated]]` and return `nullptr` (see `CandlestickPlot`).

Add a test file as described under Tests below.

JSON Report Support
=============================

In `src/reporting/reportbuilder.h`:

- Include the graph's header.
- Declare `LoadIshikawaDiagram()`, following the existing loaders (it takes `graphNode`, `canvas`, `currentRow`, and `currentColumn`).

In `src/reporting/reportbuilder.cpp`, add a type string to the dispatch chain:

```cpp
if (type.CmpNoCase(L"ishikawa-diagram") == 0)
    {
    return LoadIshikawaDiagram(graphNode, canvas, currentRow, currentColumn);
    }
```

Implement the loader next to similar graphs (e.g., `src/reporting/report_builder_business_graphs.cpp`):

1. Look up the dataset from `m_datasets` by the `"dataset"` property.
2. Read the variables or other graph-specific properties using `ExpandConstants()`.
3. Construct the graph, apply options, and call `SetData()`.
4. Call `LoadGraph()` at the end to apply the common properties (title, legend, etc.).

If the graph has new enum options, add the string conversions to `src/reporting/reportenumconvert.h`.

Saving
=============================

In `src/app/wisteriaapp.cpp`:

- Add the graph's type string to the function that maps a graph to its JSON type  (the `IsKindOf()` chain that returns `_DT(L"bullet-chart")` and others).
- Add the graph's icon name to the function that maps an item to its icon.

In `src/app/wisteriadoc.cpp`, add a branch for the graph in the function that writes type-specific properties. Only write options that differ from their defaults.

If the graph derives from another graph that is already in these `IsKindOf()` chains, place the new check before the parent's.

Enums and Gallery
=============================

In `src/base/enums.h`:

- Add a value to `GalleryItemType`, appending it to the end of the enum.
- If the graph belongs to a new category, add a value to `GalleryGroup`.

In `src/ui/controls/objectgallery.cpp`:

- Add the JSON ID string for the new `GalleryItemType`.
- If a new `GalleryGroup` was added, add its display name and icon to `GetGroupDisplayName()` and `GetGroupIconName()`.

In `src/app/wisteriaapp.cpp`, add an entry for the graph to the gallery item table (type, display name, icon, and group).
Entries of the same group should be adjacent.

In `src/ui/dialogs/editors/insertpagedlg.h` and `.cpp`:

- Declare and implement `DropIshikawaDiagram()`.
  (It shows the insert dialog and places the graph in the cell.)
- Add a `case` for the new `GalleryItemType` that calls it.

Icons
=============================

Add the SVGs to `res/images/`:

- A graph icon (e.g., `ishikawa.svg`), used by the gallery, menu, and dialog.
- A category icon (e.g., `chart-spc.svg`), only if adding a new ribbon category button.

The resource file lists are generated by `cmake/ListFiles.cmake`, so re-run CMake after adding files.

Insert Dialog
=============================

Create `src/ui/dialogs/editors/insert_ishikawa_diagram_dlg.h` and `.cpp`,
deriving from `InsertGraphDlg`.

- In the constructor, call `CreateControls()` and `FinalizeControls()`.
- In `CreateControls()`, call `InsertGraphDlg::CreateControls()` first.
  Then add the graph's own page(s) to `GetSideBarBook()` and finish with `CreateGraphOptionsPage()` and `CreatePageOptionsPage()`.
- Use `CreateDatasetChoice()` for the dataset selector, and `GetSelectedDataset()` and `GetSelectedDatasetName()` to read it back.
- Use validators (e.g., `wxGenericValidator`) to connect values to controls.
- For graphs that take columns, use a `VariableSelectDlg` with `GetParameters()` and `MakeVariableList()` (see `InsertBulletChartDlg`).
- Implement `Validate()` to check required fields.
- Implement `LoadFromGraph()` for the edit flow.
  Call `LoadGraphOptions()`, `SelectDataset()` using the graph's `"dataset"` property template, set the dialog's values, and then call `TransferDataToWindow()`.
- Implement `BuildIshikawaDiagram(const Graph2D* oldGraph = nullptr)`:
  1. Construct the graph and (if editing) copy the old graph's ID via `SetId()`.
  2. Call `ApplyGraphOptions()` and `ApplyPageOptions()`.
  3. Apply the dialog's options and call `SetData()`.
  4. When editing, call `WisteriaView::CarryForwardProperty()` for the dataset and each variable
     so that any `{{placeholders}}` the user did not change are preserved.
     When inserting, call `SetPropertyTemplate()` for the dataset and each variable.

Data Guide
=============================

The first page of the insert dialog is a "Data Guide" that tells the user how to lay out their data.
`InsertGraphDlg::CreateControls()` adds it automatically when the dialog's `GetDataGuide()` override returns a non-empty `DataGuide` (see `src/ui/controls/dataguidectrl.h`).
The page is added before the dialog's own pages, which is why a derived dialog must call `InsertGraphDlg::CreateControls()` first.

Override `GetDataGuide()` in the insert dialog:

```cpp
DataGuide InsertIshikawaDiagramDlg::GetDataGuide() const
    {
    DataGuide guide;
    guide.m_title = _(L"Ishikawa Diagram");
    guide.m_iconName = L"images/ishikawa.svg";
    guide.m_summary = _(L"Shows the possible causes of a problem, grouped into categories.");
    guide.m_requirements = _(L"One categorical column of causes for each branch.");
    guide.m_shape = DataGuideShape::Wide;
    // ...
    return guide;
    }
```

The fields of `DataGuide` are:

- `m_title`, `m_iconName`, and `m_summary`: The banner at the top of the page.
- `m_requirements`: What one row of the dataset represents.
- `m_shape`: `DataGuideShape::Long` (a row per observation, a column per variable), `Wide` (a row per subject, with repeated measures spread across columns), or `Unspecified` (no layout sketch is shown).
- `m_parameters`: Every variable the graph can use, as a `DataGuideParameter`.
- `m_prerequisites`: Things that must be in place that aren't columns
  (e.g., labels assigned to columns after importing).
- `m_examples`: Sample datasets.
- `m_missingData`: What happens when a value is missing, one statement per variable.
- `m_notes`: Additional remarks.

Each `DataGuideParameter` has:

- `m_name`: This should match the label of the variable in the `VariableSelectDlg`, and the order should match that dialog's lists.
  Use a shared `GetParameters()` function so the guide and the dialog stay in sync (see `InsertBulletChartDlg`).
- `m_types`: The `Data::Dataset::ColumnImportType` values the variable accepts.
- `m_requirement`: `Required`, `Optional`, or `Conditional` (use `m_condition` to say when it is needed).
- `m_description`: How the graph uses the variable.
- `m_values`: Coded values the variable expects (shows an "Expected Values" column when present).
- `m_multiple`: `true` if the variable accepts several columns.
- `m_group`: A heading to list the variable under. Adjacent variables with the same group are listed together.

Each `DataGuideExample` is a small sample table.
Each `DataGuideColumn` in it has an `m_name` (the header shown) and an `m_parameter`, which must be the `m_name` of one of the guide's `m_parameters`.
Each row in `m_rows` must have one cell per column.

Application Integration
=============================

In `src/app/wisteriaapp.h`, add the IDs.
Use values that are not already in use (they are all offsets from `wxID_HIGHEST`, so search the codebase for the next free number before choosing one):

```cpp
constexpr wxWindowID ID_NEW_ISHIKAWA_DIAGRAM{ wxID_HIGHEST + 96 };
```

If adding a new ribbon category, also add an `ID_INSERT_GRAPH_...` ID for its button.

In `src/app/wisteriaview.h`, declare `OnInsertIshikawaDiagram()` and `EditIshikawaDiagram()`.
If adding a ribbon category, also add a `wxMenu` member for it.

In `src/app/wisteriaview.cpp`:

- Include the dialog's header.
- Bind the menu ID to `OnInsertIshikawaDiagram()`.
- Add the graph to the menu with `appendItem()`.
- Add a branch to the edit-graph routing (where `IsKindOf()` checks dispatch to the `Edit...()` functions).
- Add the graph to the table that maps menu IDs to gallery items and class info.
- Implement `OnInsertIshikawaDiagram()` and `EditIshikawaDiagram()`.
  The edit function opens the dialog in `EditMode::Edit` (or `EditMode::Insert` when pasting as new), calls `LoadFromGraph()`, and builds a new graph (the old one is not mutated in place).
  Both functions place the graph with `PlaceGraphWithLegend()`.

If adding a new ribbon category, also:

- In `src/app/wisteriaapp.cpp`, add the dropdown button to the graph button bar with `AddDropdownButton()`, and give it a key tip.
- In `src/app/wisteriaview.cpp`:
  - Bind `wxEVT_RIBBONBUTTONBAR_DROPDOWN_CLICKED` for the button to `OnGraphDropdown()`.
  - Add the button to the list of enabled buttons.
  - Add a branch in `OnGraphDropdown()` that pops up the category's menu.

Tests
=============================

Add `tests/gui-tests/ishikawadiagramrendertests.cpp`.
Use the helpers in `tests/gui-tests/graphrenderharness.h` (`MakeCanvas()` and `LayOutOffscreen()`) to lay out the graph offscreen, and then check the number of objects it produced.
Also test that `SetData()` throws on a missing column.
Tag the tests with `[ishikawadiagram][render]`.

The test file lists are generated by `cmake/ListFiles.cmake`, so re-run *CMake* after adding the file.
